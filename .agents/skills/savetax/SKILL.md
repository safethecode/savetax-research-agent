# SaveTax

현재 요청에 필요한 근거를 읽고, 비교·계산·본문을 완성한 뒤 위임된 접수를 진행한다. 이미 끝난 확인을 반복하기보다 남은 문제를 해결한다.

## 시작

1. 현재 채팅의 대상·위임과 기존 접수 원장을 확인한다. 저장소의 `research/README.md`는 최신 기록의 진입점이다. 과거 목표액·날짜별 한도·담당 배정을 새 작업에 자동 적용하지 않는다.
2. 작업에 맞는 참고 문서 **하나부터** 읽는다. 다른 문서는 해당 단계가 필요할 때 연다.

| 후보 조사·동일품/대체품·가격·수량 계산 | [research.md](references/research.md) |
| 신규 접수·revision·불명확한 점수 POST 복구 | [submission.md](references/submission.md) |

## 공통 판단

- 검색 결과, 실제 판매 관측, 사양 검토, 산술 예상액, 공식 접수, 심사 인정, 실제 예산 절감은 각각 다른 상태다. 모르는 금액·조건은 `null`로 둔다.
- C·Q는 공식 fact 값을 사용한다. B는 같은 단위·세금 기준에 맞춘 실판매 총비용이다. `Σ floor(max(C − B×Q, 0))`를 Decimal로 계산하고 관련 fact·계약·납품요구·라인 번호를 보존한다.
- 동일 모델과 대체품을 구분한다. 실제 사양 열위·필수 구성 누락을 문구로 없애거나 미확인 비용을 0원으로 만들지 않는다. 설치·보증·대량 재고 확약을 모든 후보의 새 조건으로 추가하지 않는다.
- 제출까지 이미 위임받았다면 같은 승인을 다시 묻지 않는다. 조사·정리 요청만으로 새 접수·철회·예약을 만들지는 않는다.
- 개인 가이드와 키는 출력·커밋하지 않는다. PAT는 허용된 공식 Authorization 헤더에만 사용한다. 판매처·검색·브라우저 프로세스에는 전달하지 않는다. 업로드 토큰은 공식 업로드 주소에만 보낸다.

## 확인을 끝내는 기준

저장된 원문·계산·검토 본문 해시가 같으면 그 결과를 재사용한다. 재열람·재계산·재리뷰는 원문/본문/정책 변경, 미해결 오류, 현재 상태가 필요한 작업 때문에 수행한다. 접수 직전의 가용 상태·현재 판정·기한 확인은 별도다. 신규 접수·revision 직전 개인 가이드 전체 재독 의무는 유지한다.

기본 완료 확인은 **영수증 + 공식 GET 한 번**이다. 본문·대상 ID·첨부가 맞으면 기록하고 다음 건으로 넘어간다. 응답이 불명확하면 기존 멱등 키를 보존해 조회부터 하며 새 키로 중복 전송하지 않는다. 401/403은 인증 문제로 남기고 같은 인증 요청을 반복하지 않는다. 429는 응답의 재시도 조건을 따른다.

## 남길 결과

건별로 원문/관측 시각, 사양 차이, 계산과 관련 번호, 최종 본문, 멱등 키, 영수증, 공식 확인 결과를 한 작업 폴더에 보존한다. 공개 원장에는 접수 상태와 금액의 의미를 구분해 적고, 원본·개인 자료는 `work/`에 둔다. 실제 업로드한 바이트는 고정하며 표시용 문서를 다시 생성해 덮어쓰지 않는다.

답변은 처리 건수·접수 결과·실제로 남은 문제와 파일 링크를 먼저 제시한다. 가격 근거가 없거나 재심 결과가 나오지 않았다면 해결·인정 완료로 세지 않는다.
