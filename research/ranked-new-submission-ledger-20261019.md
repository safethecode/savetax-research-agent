# 신규 접수 후보 원장과 금액순 처리 기준

2026년 10월 19일 사용자의 마지막 정정인 “너무 낮으면 안 된다. 차라리 다 기록해두고 높은 가격순으로 접수”를 반영했다. **실제 판매 근거와 완성 구성을 검증한 대회 예상 절감액의 내림차순**으로 신규 접수를 진행한다. 판매 단가·조달 총액·검증 전 예상액은 접수 순위를 대신하지 않는다.

1억 원은 조사 우선순위의 참고값이다. 사용자가 확정한 절대 하한으로 만들지 않는다. 그보다 작은 후보도 근거와 관련 번호를 보존하되, 큰 후보의 검증에 앞서 한도를 소모하지 않는다. 앞선 2억·3억·10억 원 기준을 이번 신규 접수의 탈락 문턱으로 다시 적용하지 않는다. 기존 접수는 유지한다.

전체 기록은 [후보 원장 JSON](ranked-new-submission-ledger-20261019.json)에 있다. 현재 가격이나 상태를 다시 검증하지 않은 과거 금액은 `historical_recorded_amount_not_current_verified_krw`로 남겼다. `verified_expected_saving_krw`와 섞어 합산하지 않는다.

**후속 정정:** 처음 만든 재검증 목록은 기존 문서의 중첩 차액과 다른 필드명을 빠뜨렸다. 따라서 아래 원장 규모가 기존 대기 후보의 재검증 완료를 뜻하지 않는다. 사용자의 지적 후 기존 물리적 품목 58개의 가격 시나리오를 다시 찾아 상태를 조회했고, 33개가 available이었다. 이 목록에는 실제 판매가 기반 산술 외에 목표 단가와 가격별 민감도도 들어 있으므로, 그 숫자를 현재 확보액이나 접수 순위로 사용하지 않는다. 원문 경로·시나리오 종류와 새 직접 확인 결과는 [기존 후보 재검토](existing-backlog-recheck-20261019.json)에 보존했다.

최신 공식 계정 조회에서 남은 신규 접수 기회는 **35회**였다. 원격 저장소 동기화에서 별도 병행 작업의 기존 대기 후보 23454735 신규 접수를 발견하고, 공식 상세 API와 계정에서 이를 직접 대조했다. [공식 영수증](https://hackathon.savetax.now/#/submission/4017ca55-614a-49f6-b08a-8730b75f3d40)은 accepted·revision 1·예상액 668,418,261원이다. 조회 당시 `amount_kind=provisional`, `verification_status=not_started`, `lint_status=unreadable`, `held=false`, `rejected=false`였다. 최종 인정액이 아니며, 이 실행에서 직접 접수한 실물 후보로 세지 않는다. 해당 접수 본문과 근거는 [병행 작업의 접수 기록](linuxserver-23454735-submitted-20261019.md)에 있다.

계정 조회 URL과 시각은 원장 `account_limits`에 있다. 접수 직전에는 규칙·가격·상태·한도를 다시 읽고, 개인 지침 전체도 비밀값을 마스킹한 뒤 확인한다. 이미 등록된 품목과 반려 품목을 이 원장을 이유로 자동 재접수하지 않는다.
